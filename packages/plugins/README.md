# Three Forge Studio 插件架构指南 (Plugin Architecture Guide)

本文档旨在说明 `packages/plugins` 目录下各个标准插件的设计模式及文件组织规范。**未来的 AI 助手或开发者在接手、修改或新建插件时，只需阅读此文件即可快速了解整个插件项目的工作原理和各文件的核心作用。**

## 插件标准目录结构与文件职责

在 Three Forge Studio 中，为了做到关注点分离，使得“编辑器态”与“独立运行态(Runtime)”解耦，避免打包时引入不必要的 UI 或编辑器依赖，每个独立功能插件（例如 `camera-animation`、`interaction`、`label` 等）通常包含以下标准化的同名文件：

### 1. `core.ts` (核心业务层)
- **作用**：负责实现插件的核心业务逻辑，直接与 Three.js 引擎层级交互。
- **职责**：
  - 管理底层状态和引擎 API 调用（如控制相机位姿、执行 GSAP 动画、对象的显隐、事件派发等）。
  - 是真正“干活”的模块，绝对不依赖任何 Vue 组件或高级编辑器环境上下文。
  - 同时被编辑器环境和纯净渲染环境（Runtime）引用。

### 2. `editor.ts` (编辑器适配层)
- **作用**：扮演编辑器 UI 层与底层 3D 引擎数据（如 `scene.userData`）之间的通讯桥梁。
- **职责**：
  - 处理在编辑器开发/调试态时，临时修改数据的“存”与“取”。
  - 供 UI 面板调用，将面板表单中更改的配置数据深拷贝并同步到场景 `userData` 中。
  - 触发引擎层的视图更新或自动保存钩子（如 `onSceneGraphChanged`），让编辑器感知到状态的变化。

### 3. `serializer.ts` (数据持久化层)
- **作用**：专门处理插件业务数据在项目工程文件（JSON）中的保存（序列化）与读取（反序列化）。
- **职责**：
  - 实现 `ForgePlugin` 接口（包含 `name`、`version`、`serializeRoot`、`deserializeRoot`）。
  - **保存项目时**：提取 `scene.userData` 中的特定插件数据，作为扩展节点写入导出的 JSON 中。
  - **加载项目时**：解析外部读取到的 JSON 扩展节点，并将其恢复挂载到底层场景对象的 `userData` 中。

### 4. `runtime.ts` (运行态组装层)
- **作用**：为非编辑器的纯渲染环境（如 Preview 预览页、发布的独立打包应用）提供的轻量化入口包。
- **职责**：
  - 内部仅组装挂载 `core.ts` 和 `serializer.ts`。
  - **坚决不能引入 `editor.ts` 或任何 UI 组件**（避免将整个 Vue 框架或繁重的编辑器组件树打包进纯渲染引擎中导致体积臃肿）。
  - 向外代理暴露供业务方直接调用的便捷 API。

### 5. `types.ts` (类型声明)
- **作用**：定义插件专属的数据结构与 TypeScript 接口规范。
- **职责**：
  - 规范插件内部的数据流格式。
  - 被整个插件内的所有模块共用，保持各层级传递数据时的强类型约束。

### 6. `index.ts` (插件总入口 / 编辑器 Bundle)
- **作用**：向主程序（即带有编辑器 UI 的主项目）暴露完整的插件 Bundle 注册对象。
- **职责**：
  - 组装并暴露一个符合 `ForgeAppPlugin` 接口定义的对象。
  - 注册 `ui`：挂载侧边栏 Tab 标签文字及对应的 Vue Panel 面板组件。
  - 注册 `serializer`：挂载持久化拦截器。
  - 注册 `core` 与 `runtime` 核心逻辑模块。
  - 集中导出 (`export * from '...'`) 插件内其他模块的变量与类型，方便外部引用。

---

## 插件开发原则总结

1. **严格分离 UI 与逻辑**：`core.ts` 不能感知 Vue 或 UI 视图的存在，UI 操作底层和底层反馈 UI 都必须通过标准的 API 方法调用或抛出引擎事件 (`dispatchEvent`) 来完成。
2. **Runtime 纯净度**：凡是要提供给最终用户在网页上纯渲染浏览使用的功能，都必须保证通过 `runtime.ts` 引入时，剔除了所有庞大的编辑器库和视图框架。
3. **数据中心化**：插件的配置与业务数据应当统一挂载或存储在底层的场景节点对象（如 `scene.userData`）中。通过 `editor.ts` 在编辑时双向同步，通过 `serializer.ts` 在存盘时固化。
